# AGENTS.md — NihonGO

## Brand
- Product: NihonGO; mascot/companion: Momo.
- Momo's appearance must follow the official logo asset in `assets/nihongo-logo.png`.
- Visual direction: modern EdTech with cream, orange, navy, and pastel skill colors.
- Keep the mascot friendly and playful, but the overall product UI polished and credible.

## Before changing code
1. Read `SKILL.md` and `DESIGN.md`.
2. Inspect the existing framework, routing, assets, dependencies, and scripts before choosing implementation.
3. Prefer existing stack and components; do not migrate framework without approval.
4. Verify the actual demo URL and feature availability before publishing.

## Content truth
- Do not invent usage numbers, star ratings, testimonials, endorsements, or results.
- Describe planned features as planned; don't present them as released.
- Replace all placeholder links before production.

## UI quality
- Use semantic HTML, accessible navigation, visible focus, responsive layouts, and descriptive image alt text.
- Respect `prefers-reduced-motion`.
- Keep motion subtle; avoid animation that blocks reading or causes nausea.
- Centralize tokens and reuse components.
- Test keyboard and touch interactions, all links, and small viewport layouts.

## Delivery
Report changed files, checks actually run, and remaining configuration steps. Never claim a build or test passed if it wasn't run.

## Landing page content
- Preserve the existing NihonGO story and layout; extend with sections only when requested.
- Avoid decorative cherry blossoms and four-petal sparkle marks. Prefer meaningful learning/product icons.
- Treat learner counts, ratings, testimonials, prices, discounts, offline capability, refund policies, and store availability as unverified until confirmed by the product owner.
